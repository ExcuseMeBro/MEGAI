## Task containers and resource cleanup

Before starting disposable task Docker resources, run `~/.local/bin/megai-task-resources labels --repo <task-worktree> --task <unique-task-session-slug>` and apply all returned `io.megai.repo`, `io.megai.task`, `io.megai.disposable=true` labels explicitly to task containers, built images, networks and disposable named volumes; Compose service labels do not propagate to these. Use isolated Compose project names. Never label shared/dev/production data disposable; persistent volumes stay external/unlabelled. Prefer `--rm`, tmpfs for ephemeral data, and bounded container CPU/memory/logs.

After verified remote dev delivery and before removing the clean `task/*` worktree, quiesce only that task's runners, run `~/.local/bin/megai-task-resources cleanup --repo <task-worktree> --task <same-slug> --context kiri --commit <full-delivered-HEAD-SHA>` to preview, inspect the exact resources, then repeat with `--apply` (the helper checks remote-dev ancestry itself). Run synchronously as part of delivery for Pi, Codex and Claude, not via hooks/timers/background automation. A missing tool, refusal or failed cleanup is a reported blocker, never permission to substitute global prune. Record results, then remove the merged worktree/branch normally. Existing unlabelled resources are never adopted or deleted.

Leftovers from finished or interrupted sessions are reclaimed only with the same tool, never ad hoc: `sweep --context kiri --anonymous-volumes` (preview first), `sweep --temp-clusters` (orphaned temp PostgreSQL servers), `sweep --idle-servers`, and `caches` (unreferenced Gradle version caches only). Disk pressure is measured, never guessed: `disk --kiri` is read-only; `disk --apply --xcode --builders --temp-clusters` removes only named rebuildable artifacts; `disk --apply --kiri` requires the Kiri VM stopped and follows the sequence in MEGAI `docs/task-resources.md`. Never reclaim space with `rm -rf` on caches, SDKs, device support, sources, `node_modules` or another session's build/temp directories, and never delete named/persistent data volumes.

## Memory and process bounds

Host RAM is shared, not per-task. Before any build, emulator, container stack or browser run, check `~/.local/bin/megai-task-resources mem` and skip or defer heavy work while swap is above half of its total or the compressor exceeds a fifth of RAM. Bound every process you start: JVM `-Xmx` at most 3g with `--no-daemon --max-workers=2`, emulators with `-memory 2048` and AVD `hw.ramSize` at or below 2048, one heavy job at a time. Stop your own dev server, emulator, file watcher and container stack before delivery and before an unrelated heavy job; another session's are not yours to stop. Start long-lived processes only through the task runner that will stop them; never leave a `nohup`/`setsid`/background process behind after a turn, and never hoist a process into the background just to avoid a timeout. `sweep --idle-servers --apply` stops only dev servers older than `--min-idle-hours` (default 8) with zero established clients; emulators, IDEs, Docker VMs and other sessions' JVM daemons are reported by `mem`, never auto-stopped.

Never run global Docker/volume/cache prune after a task, remove persistent/shared volumes, stop unrelated containers/JVMs, or truncate/reset Kiri's disk. Shared BuildKit uses GC (this Mac: 8 GiB target, 300s idle), not per-task prune; keep the Kiri 64 GiB disk ceiling. For isolated Gradle checks use `--no-daemon --max-workers=2` and bounded JVM memory; don't rewrite global settings or kill other sessions' daemons. Details: MEGAI `docs/task-resources.md`. Preserve provider/model/thinking settings.
