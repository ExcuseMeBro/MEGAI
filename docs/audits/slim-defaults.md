# Slim default stack verification

## Acceptance

The nine existing stack entries plus Caveman are installed/discoverable and selected by default when their purpose matches the task. This does not mean ten compulsory tool calls, shell-wide command rewriting, automatic memory ingestion or startup indexing.

- Caveman: bundled complete MIT core from caveman-installer 2.2.0, default full style. Six intensities, examples and Auto-Clarity are retained. MEGAI metadata and integration guards preserve uncertainty, acceptance, required checkpoints and durable normal-mode opt-out. Unsupported percentage guarantees are removed. No companions, engines or hooks.
- codedb/zvec: structural/intent lookup defaults; local indexing on demand.
- RTK: supported discovery-output default. Tests, lint, build, compound commands and full review diffs remain native/raw; original exit status is authoritative.
- Plane task-flow/worktrees: mandatory boundaries, observable acceptance and agreed branch delivery.
- Ruff: non-mutating checks for changed Python. Matt/UX kits: task-matched bodies loaded automatically, not entire kits.
- Memory: relevant recall with lazy local startup; saving requires an explicit persistence request. Existing process/port ownership remains protected.

## Evidence

- Initial regression: the two new default/ownership tests failed against the previous wiring before implementation.
- `bash tests/slim-distribution.sh`: 26 tests passed, including all-client default wiring, old-receipt upgrade, custom-asset refusal, user opt-out preservation, uninstall and no-prewarm contracts.
- `bash tests/pi-performance.sh`: 2 tests passed.
- Ruff integration, orchestration policy, changed-Python non-mutating Ruff and `git diff --check`: passed.
- Real Pi resource loader after local deployment: 58 skills, exactly one Caveman, one lazy MCP adapter, zero diagnostics. No model requests or extra RTK extension.
- Disposable local fixture: codedb found `calculate_invoice_total`; zvec hybrid FTS/vector search returned the matching `invoice.py:1-3`; RTK retained the expected commit subject and filename.
- Local memory readiness: service reports `service=agentmemory`, `status=ok`; REST listens on `127.0.0.1:3111`. A stale legacy PID record was archived only after proving the process absent and port unoccupied. No memory save or session import was performed. Cold startup required a bounded readiness wait; a spawned process is not itself readiness proof.
- Ten protected host configuration/auth/model/index file hashes remained unchanged by this refinement. All-client doctor passed; OMP policy is installed but the host lacks the OMP CLI, so OMP launch is unverified.
- Independent Sol review passed after replacing the initially abbreviated Caveman adaptation with the full core and strengthening regression assertions.

## Performance limits

Five local `megai pi --version` samples before/after measured median launch times of 0.393 s and 0.370 s. This only covers local wiring and CLI version startup. The small uncontrolled sample does not establish faster task completion, lower model-token usage or better code quality. No daemon/index/model work was added to harness startup. Task-specific acceptance tests and review remain the quality gate.

## Delivery and recovery

This change belongs to the persistent `slim` branch, not `dev`/`main`. Local application uses the unchanged source installer and receipt-owned all-client wiring, retaining private numbered recovery manifests under `~/.megai/backups/`. Explicit user resource exclusions remain authoritative. Restart each harness to load new policies and shed old conversation context; `/reload` alone does not remove prior context.
