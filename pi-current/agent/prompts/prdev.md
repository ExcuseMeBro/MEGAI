---
description: Open or reuse a verified dev-to-main pull request for the current project (no merge)
---

`/prdev` authorizes a necessary normal push of **verified** `dev` to its verified remote and creating or reusing a `dev` → `main` pull request. It does not authorize merging or pushing `main`, deleting unrelated resources, other projects or Plane synchronization. Any `dev` delivery still requires the task-owned cleanup boundary before review; this command does not waive it. Pellet is the only execution tracker: no `pi-workflow`, Plane MCP/REST or Plane evidence writes here. `/splane` alone syncs Plane.

1. Resolve the project from `.pi/project.json` or verified repository identity and cover every configured repository. Determine the intended forge/destination from explicit project policy, then verified remote identity and both fetch/push URLs; do not silently redirect a fork. Use the authenticated matching CLI (`gh` for GitHub, `glab` for GitLab). Preserve dirty/busy checkouts without committing, stashing, resetting or rebasing foreign work. Fetch remote refs and capture exact `main` base and `dev` head SHAs. Missing `main` is a blocker, not permission to create it. If `git rev-list --count <main-sha>..<dev-sha>` is zero, report no PR needed without creating a task or pushing.
2. Paginate project-bound Pellet tasks (`query_tasks` with `envelope: true`), inspect selected full tasks with `get_task`, and attach evidence to the existing task(s) whose accepted commits cover the complete `dev`-versus-`main` diff. Never fabricate evidence or infer a task from a matching title. If no applicable task exists, first check all relevant pages for duplicates and create a project-bound Pellet task through `create_task` and `rename_note`, open → in_progress, with scope, plan and acceptance; this task must not substitute for missing evidence or authorize unrelated commits. Confirm delivery, source-current checks and self-review for the **exact** proposed `dev` SHA and complete diff before any push or PR write; run missing focused/required checks and record real results on the task. Preserve existing task fields. Unknown/unrelated ahead commits, divergence, missing evidence or uncertain task ownership block publication.
3. Re-fetch/revalidate pinned heads and evidence immediately before publication; moved refs require fresh evidence and affected checks, not an unqualified retry. When a push is necessary, exclusively own the exact clean/idle target; push only `git push <VERIFIED_REMOTE> <FULL_SHA>:refs/heads/dev` (no force), then fetch and independently `git ls-remote` to confirm the advertised and fetched remote `dev` both equal the accepted SHA. Verify ancestry of every delivered SHA in local and remote `dev`. If this push completes a task's delivery, immediately attempt its safe task-owned worktree/branch cleanup per project rules before review or PR creation; retain active, uncertain or data-bearing resources with a recorded reason. On uncertain push or remote verification, retain resources, reconcile actual state, keep the task `in_progress`, and do not write a PR.
4. Look up **open** PRs for the exact base repository/`main` and head repository/`dev`. Verify an existing PR's base/head SHAs; never create a duplicate on stale or uncertain lookup. If no match after complete lookup, create a PR with a concise diff-based summary and actual test results, using a structured body or `--body-file`. Read back URL, state, repositories, direction and head/base SHAs; revalidate if refs moved. Never leak private text or credentials. A PR is not main delivery: leave the existing Pellet tasks `in-review`, not `completed`; record verified PR URL/SHAs and timestamp on them. Revalidate Pellet state and read back uncertain writes. Report each repository's PR URL or precise blocker. Browser review is only `/rwbrowser` unless existing acceptance requires it.
