---
description: Deliver accepted project tasks to verified local and remote dev using Pellet
---

`/mdev` authorizes reviewed, accepted **task-owned** commits to local `dev` and a normal push to the verified remote `dev`. It does not authorize main, releases, force pushes, unrelated commits or other projects. Pellet alone owns task selection, evidence and review. Do not run `pi-workflow`, use Plane MCP/REST, or sync Plane here; `/splane` is the only Plane sync boundary.

1. Resolve the project from `.pi/project.json` or verified repository identity. Inventory each configured repository's worktrees, task branches, local `dev`, and fetched remote `dev` with native Git. Match candidate work to its existing Pellet task in the project folder; paginate `query_tasks` (`envelope: true`) and `get_task` for selected tasks. Never infer ownership from a branch name alone, adopt another task's checkout, invent an ID or create a substitute task. For each candidate, confirm scope, frozen criteria, source-current checks, self-review, complete exact commit range, repository identity, and task ownership. Do not turn an incomplete or unknown row into an empty sweep.
2. Independently verify the fetch and push URLs of the intended remote, fresh fetched `dev`, and every proposed SHA. Inspect **all** commits local `dev` would gain; unknown/unrelated ahead commits, divergence, stale checks, dirty/busy integration target, actual concurrent writer, lock or uncertain ownership block that repository. Do not stash/reset foreign work, force push, auto-merge/rebase or change targets to evade a blocker. An open session, cwd or app by itself is not a blocker. Keep one writer per exact target through push, verification and cleanup; recheck pinned heads before shared writes. Resolve task-local issues only inside a verified task-owned worktree, then rerun affected checks.
3. On the verified integration target, fast-forward with `git merge --ff-only --no-overwrite-ignore <FULL_TASK_SHA>`. Push only the accepted exact tip: `git push <VERIFIED_REMOTE> <FULL_SHA>:refs/heads/dev`. Fetch again and independently `git ls-remote` the same target; fetched and advertised heads must agree. Verify **every** delivered SHA is an ancestor of both local `dev` and freshly fetched remote `dev`. Reconcile remote movement before claiming delivery. A failed or uncertain push/verification leaves resources intact and the Pellet task `in_progress`; never assert success from an attempted push.
4. Immediately after complete affected-repository local **and** remote verification, attempt cleanup before review or unrelated work. Inventory tracked, untracked and ignored content in each task-owned worktree; preserve necessary data in a private verified backup. Recheck release/ownership, clean worktree, exact branch tip and local/fresh remote ancestry. Remove only an eligible released task worktree with normal `git worktree remove`, verify removal from Git and disk, then delete only its proven-merged local task branch with `git branch -d`. Retain and report active, uncertain, dirty, data-bearing, unmerged or foreign resources. Never terminate a user's session to make cleanup possible.
5. Append concise evidence to the **same Pellet task**: project, repository path, verified remote and both URLs, full accepted SHAs, checks/self-review, integration/push/fetch/ls-remote/ancestry results and timestamp, local/remote tips, cleanup attempts and retained paths. Revalidate its identity and status before writes; do not blindly retry uncertain Pellet writes—read it back. After complete delivery, set Pellet status to `in-review` (not a tag). Partial delivery stays `in_progress`. Report delivered, blocked and retained candidates separately with exact SHAs and evidence. `/prdev` owns a later `dev` → `main` PR, and `/rwbrowser` is user-invoked except pre-existing required browser acceptance.
