# Project work

1. Read applicable AGENTS.md and `.pi/project.json`; resolve the Brokan project from that config or verified repository identity. For broad discovery, read [context-economy.md](context-economy.md). If no project maps to the repository or the user says no task is needed, work and deliver without a Brokan task; never stop to ask which project.
2. Inspect relevant Brokan project and human tasks before creating a new task; reuse the selected task for refinements. Set `todo` then `doing` before edits, with scope, short plan and acceptance criteria in the description. Brokan is the sole task tracker and acceptance authority; never synchronize it with Plane or use `pi-workflow`.
3. For Git changes create or reuse a task-owned worktree on `task/<slug>` from the newest dev (`git fetch <remote>`, `git worktree add -b task/<slug> <path> <remote>/dev`), or an explicitly approved persistent branch. Never edit, stage or commit source directly on dev/main or in another task's worktree. For non-Git runtime edits make a private pre-change receipt/backup and run focused checks. For guarded changes use the source-current formal acceptance gate with a frozen Brokan schema-4 contract; historical Plane contracts remain archival.
4. Run the relevant tests/gates, fix failures until green, self-review the complete diff and commit. Then deliver with STANDING APPROVAL — never ask the user whether to merge, push or clean up. Sync: `git fetch <remote>`, bring local dev up to `<remote>/dev`, `git rebase dev` in the task worktree (or `git merge dev`). Commits from other branches on dev, divergence and conflicts are not blockers: resolve them, rerun tests. Integrate in the dev checkout with `git merge --ff-only task/<slug>` and push `git push <remote> dev` (retry the sync if rejected; if uncommitted changes in the dev checkout block the fast-forward, commit them to a new `wip/<date>-<slug>` branch, `git switch dev`, and continue). Confirm with `git fetch <remote>` and `git merge-base --is-ancestor <FULL_SHA> <remote>/dev`. Never force-push.
5. Immediately clean up: leave the worktree, `git worktree remove <path>`, `git branch -d task/<slug>`, and `git push <remote> --delete task/<slug>` if it was pushed. Your own merged worktree is released even though your session used it; disposable untracked build output may be removed with `git worktree remove --force <path>`. Uncommitted changes anywhere are committed (WIP commit on their branch), never discarded. A session, dev server or Flutter run holding a checkout you must change is stopped automatically by exact PID (`lsof +D <path>`, `kill <PID>`), never your own process and never broad `pkill`/`killall`; report what you stopped. An unmerged WIP branch is kept; its worktree may be removed.
6. Note the merged SHA, push and cleanup result in the Brokan task and set status `review`; leave `done` to the user's decision. Main promotion and publishing require separate explicit approval and verified inclusion of every delivered SHA in remote main. Do not invent Git delivery for runtime-only work.
