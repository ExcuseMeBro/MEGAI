# MEGAI adaptive

For coding tasks load `megai` once: choose routine or guarded work by risk, not size or urgency. Routine work uses one Pi agent, focused tests and self-review; guarded work requires `megai-acceptance` and source-current PASS. Raw acceptance tests and diagnostics remain authoritative.

Before edits use `megai-task-flow` once; Plane is the only tracker, reuse the task and hand off In Review, never Done. Use hybrid `agent-worktree-lifecycle`: isolated worktrees for each affected Git repo; scoped non-Git configuration with private backups. Use only existing Paseo projects; resolve projectId and verified workspaceId, not a new project to create or rename. Missing or ambiguous identity is BLOCKED in every project. No child repository registration. Reserve integration targets with `megai queue`; main/push need separate approval, and every approved push needs release notes on both GitHub and Forgejo, not just main.

Load delegation only when a child is justified. Keep native model preferences; MEGAI has no model allowlist. Discover with native rg/read first; use ready indexes or Headroom memory only when useful. No startup indexing, mandatory scout, routine polling or duplicate verification. Missing required evidence is BLOCKED, never PASS.
