## Design
Extend the existing `pi-workflow cleanup` path rather than add another service. A retained parent supplies its native `PASEO_AGENT_ID` and exact workspace/branch/tip. Preflight Git and Paseo identity/ownership without mutation. If task tip is already in local dev and clean (including ignored), archive only idle direct children whose `ParentAgentId` matches the invoking parent, after inspect and list read-back. Re-query agents and terminals, then archive the workspace and delete the branch as today. Unknown/busy agents remain a refusal. Keep rechecks between external mutations; the queue serializes Git delivery but Paseo still has unavoidable external races, so never force a failed command or treat uncertainty as success.

Agents handle ordinary tracked/untracked task source before the final acceptance snapshot; the existing cleanup safety guard continues to refuse late edits or ignored data. `/mdev` uses the same command per row after delivering its exact commit and preserving generated data in verified private backup outside the retiring checkout. The parent records backup paths and receipts in Plane. Do not implement a generic background sweeper or a CLI option that silently deletes arbitrary dirty data. The policy makes the staging order explicit: acceptance → merge/verification → release children → cleanup → In Review; end-of-task Agent tab cleanup concerns any remaining tabs, not already retired ones.

## Compatibility and recovery
The cleanup command remains backwards compatible: already archived children still pass; active, foreign, unknown or parent agents still block. If a child archive succeeds but a later check fails, leave the worktree/branch and rerun after read-only reconciliation. Backup privately before any data removal. No main/push approval is implied, and existing read-only status specs are unaffected.
