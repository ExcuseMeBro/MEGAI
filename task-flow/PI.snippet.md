## MEGAI task flow
The parent loads `megai-task-flow` once at task start/resume and completes its Plane start boundary before project edits. Reuse the active linked work item through edits and follow-up refinements; delegated children inherit that identity and never mutate Plane or `.todos`. Resolve exactly one project by Git-root folder name, consuming every Plane project page; zero or multiple matches require the user. Resolve exactly one project work item the same way before mutation. Preserve the original `<!-- asana:GID -->` marker until its Plane pair is confirmed.

Tracked MEGAI handoff has a mandatory delivery gate: after verification/self-review, record each worker's Paseo workspace ID, worktree, branch, and reported committed tip, prove exact tip+clean state, then serially return to each current-task worker and run `megai finish --verified --target dev` once per safely mergeable worker. `finish` handles one current worktree per invocation, so repeat it serially until all safely mergeable current-task branches are merged into `dev` and pushed; the first call creates/reuses exactly one `dev` → `main` PR/MR and later calls reuse it. A nonzero call may leave `dev` advanced: reconcile before retry and do not archive failure. Confirm each recorded tip is an ancestor of pushed `dev`, perform a complete request lookup proving exactly one open PR/MR (finish's first result is not cardinality proof), clean every safely merged current-task worktree/local task branch, archive each Paseo workspace only after cleanup, and pass the final current-task inventory gate. Duplicate/uncertain lookup or missing push, PR, cleanup, or Paseo archive blocks In Review. Orphan task-local branches require explicit ownership, merged-tip proof, and non-force `git branch -d` deletion. Preserve `dev`, `main`, primary, orchestrator, and unrelated, dirty, unmerged, failed, or ambiguous work; use no global branch sweep. Only then hand off at Plane `In Review`, with the work item incomplete; main promotion remains separately explicit and only the user may mark `Done`.
