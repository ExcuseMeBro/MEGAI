# Risk-scaled Asana sync + task-flow + ADLC
- **Bounded fast path:** pure questions and localized copy/style/layout or presentation-only constant changes across at most three directly related files may skip Asana, `.todos`, worktrees, subagents, TDD, and commit/PR only after an explicit blast-radius check. Eligible changes MUST have an obvious acceptance condition, a focused check, and no public API/schema/auth/security/dependency/data-migration, production/CI/deployment, infrastructure, permissions, retention, destructive-behavior, or operational-config impact.
- Fast-path execution is one inspect/edit/check loop: batch independent reads, edit the narrowest seam, run the focused behavioral/visual/diagnostic check, self-review the changed range, then stop. Target at most eight assistant requests; exceed that only for a concrete acceptance blocker.
- **Tracked/high-risk path:** use Asana and `.todos` for multi-module or public-contract work, auth/security, schema/data/dependency migrations, production/CI/deployment or infrastructure configuration, permissions/retention/destructive behavior, explicitly tracked tasks, or explicit ship/PR requests. Create/reuse the Asana task and set `In Progress` before implementation; after verification and required delivery, set `Done` + `completed=true`.
- **Parallel implementation invariant:** when tracked work decomposes into two or more independent implementation slices, the parent is the sole integration owner and fans them out in one batch. Every writer gets one registered isolated worktree/task branch from the same `dev` baseline (`isolated: true` in OMP); assign non-overlapping file ownership and serialize shared-file or dependency-ordered boundaries.
- Reuse linked task/project/section GIDs. Use `asana_search_objects` only when identity is unknown; never use premium `search_tasks`. Never discover or sync Plane, Jira, or another tracker unless the user explicitly asks.
- **task-flow** (`~/.claude/skills/task-flow/SKILL.md`) is the local execution mirror for tracked/high-risk work. After the Asana start boundary, add one linked line to `.todos/inprogress.md`.
- At a new tracked task or resumed session, read `todo.md` and `inprogress.md` once. Read `done.md` only to resolve prior identity or complete work. Do not re-read unchanged board files at every stage.
- **Write emoji task lines:** priority 🔴 urgent · 🟠 high · 🟡 medium · 🟢 low, then stage 📝📐🔨🧪🔍🚀. Never hand-edit `monitoring.md`.
- ADLC is required phase coverage, not one tool/model round trip per phase. Collapse spec+plan and verify+review when one evidence pass covers them; use full TDD, independent review, worktrees, and ship gates only where risk or the requested delivery requires them.
- **Dev + PR ship gate:** for tracked work that must ship, default primary work to `dev` and create task worktrees from `dev`. After tests/review, run `megai finish --verified --target dev` to merge when needed, push `dev`, and open/reuse a `dev` → `main` PR/MR before Asana completion. Never auto-merge `main`; delete only merged task branches/registered worktrees.
- Asana unavailable/unauthenticated blocks only work that requires the tracked/high-risk path. A failed required boundary write must be reconciled before proceeding.
- Priority markers: `!` low · `!!` medium · `!!!` high · `!!!!` urgent; no marker = medium. Only urgent preempts active work.
