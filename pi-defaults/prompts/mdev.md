---
description: Merge finished, tested task branches into dev, push, and clean them up without asking
---

`/mdev` runs the user's **standing-approval** dev delivery: every finished task branch is synced with `dev`, tested, merged into local `dev`, pushed to the remote `dev`, and its worktree/branch is cleaned up — end to end, with no approval prompt. Never ask "should I merge/push/clean up?" and never stop at "ready to merge"; asking is a defect. It does not authorize main, releases, tags, force pushes or other projects. Brokan alone owns task selection, evidence and review. Do not run `pi-workflow`, use Plane MCP/REST or synchronize task data with Plane.

Use a task-local **evidence graph**, not a background agent: Brokan task → green tests and self-review → branch synced with newest `dev` → merged and pushed `dev` → ancestry confirmed → cleanup → review. Never tune tests, acceptance or safety rules to turn a check green; fix the code. Do not create autonomous monitoring or extra approval gates.

1. Resolve the project from `.pi/project.json` or verified repository identity. Inventory each repository's worktrees with `git worktree list --porcelain`, task branches, local `dev`, and fetched remote `dev`. Match candidate branches to their Brokan task (`list_tasks`, `get_task`); a guarded change still needs its source-current formal PASS. Branches the user names, and finished task branches, are candidates.
2. Sync each candidate: `git fetch <remote>`, bring local `dev` up to `<remote>/dev` (fast-forward, or a normal merge if local `dev` has unpushed commits), then `git rebase dev` in the task worktree (`git merge dev` if a rebase is impractical). Commits from other branches or tasks on `dev`, divergence and merge conflicts are **not** blockers: resolve conflicts yourself keeping both sides' intent, fix breakage, and rerun the relevant tests until green. Self-review the final diff.
3. Integrate: in the `dev` checkout run `git merge --ff-only task/<slug>`, then a non-force push `git push <remote> dev`. If the push is rejected because remote `dev` moved, repeat step 2 and retry. If uncommitted changes in the `dev` checkout block the fast-forward, save them first: `git switch -c wip/<date>-<slug>`, `git add -A`, `git commit -m "WIP: auto-saved uncommitted changes"`, `git switch dev`, then continue; if that is impossible, push the tip with `git push <remote> <FULL_SHA>:refs/heads/dev`. Confirm once with `git fetch <remote>` and `git merge-base --is-ancestor <FULL_SHA> <remote>/dev` (`git ls-remote <remote> dev` if in doubt). No human check follows.
4. Clean up immediately: leave the worktree directory, `git worktree remove <path>`, `git branch -d task/<slug>`, and `git push <remote> --delete task/<slug>` if the branch was pushed. Your own merged task worktree is released even though your session used it. If removal refuses only because of disposable untracked build output, use `git worktree remove --force <path>`; commit anything that belongs in the change first. Uncommitted changes in any worktree are committed (on its branch), never discarded. If a Pi session, dev server or Flutter run holds a checkout you must change, stop exactly that process without asking (`lsof +D <path>` → `kill <PID>`; `kill -9 <PID>` only if it ignores SIGTERM), commit its leftovers and continue; never stop your own process or its parent, never broad `pkill`/`killall`. An unmerged WIP branch is kept, but its worktree may be removed.
5. Append a short note to the **same Brokan task**: merged SHA, push result, cleanup result. Set Brokan status `review` (not a tag). If a push genuinely failed, the task stays `doing` and you report the exact error. Report delivered and failed branches with exact SHAs, then stop. `/prdev` owns a later `dev` → `main` PR, and `/rwbrowser` is user-invoked except pre-existing required browser acceptance.
