---
description: Reconcile, review, merge and push verified task work to dev
---

Invoking `/mdev` explicitly authorizes reviewed task delivery to `dev` and an ordinary non-force push to `origin/dev` for the resolved project. It does not authorize main promotion, a force push, remote task-branch deletion, or changes to another project.

1. Load `pi-workflow`, run `pi-workflow context` and read the reported rules and `.pi/project.json`. Inspect only configured repositories. Protect `main`, `dev` and any configured persistent branches. Inventory local `task/*` refs with `git for-each-ref`, linked checkouts with `git worktree list --porcelain`, and current/fetched target SHAs. Do not assume an unlisted checkout is abandoned or exclusively owned.
2. Build a per-repository ledger of task branch, exact SHA, checkout path, Git common-dir, owner, clean/dirty/ignored state, operation state, Plane task, acceptance and parent review. Missing provenance, an active/foreign writer, conflicts or incomplete acceptance block that candidate; continue independent rows. Never stage, switch, reset, stash or overwrite another owner's checkout. Tracked or untracked task source needs its own task acceptance before integration.
3. Verify the exact candidate SHA against the Plane acceptance and focused checks. Guarded tasks require source-current formal PASS; all tasks require parent self-review. An old receipt for a different SHA is not evidence. Resolve bounded conflicts in an owned isolated checkout and reverify the result; preserve both histories. Never weaken a failed check or silently omit a candidate.
4. Reserve the exact repository vector with `megai queue plan`, `enqueue`, then `claim` under the existing Plane pair. Use `--remote-dev` only for an approved origin/dev delivery and `--target-branch dev` only when the local dev checkout is clean and exclusively owned. Follow the queue's refresh/hold/reconcile contract on moved refs, timeout or uncertain mutation. It grants no push/main approval beyond this explicit invocation.
5. In an owned integration checkout, merge the pinned candidate SHA with `git merge --no-edit --no-overwrite-ignore`. Preserve colliding ignored files in a verified private backup; never force overwrite. Run final focused checks and review on the merged SHA. Push only the validated SHA to `refs/heads/dev` with an ordinary non-force push. Read back the remote SHA and ancestry. Do not modify a dirty or busy primary checkout; report remote-only delivery separately from local-dev reconciliation.
6. Attempt cleanup only for clean, released, task-owned worktrees proven merged into the verified target; back up ignored data and evidence before removing a worktree and its proven-merged branch. Retain active, dirty, unknown or unmerged resources with explicit reasons. Keep the queue grant until delivery and cleanup are accounted for, then release it under its contract. Record exact SHAs, tests and retained resources in the same Plane task, hand off In Review, never Done without verified main delivery.

Report a ledger of merged, held and retained rows with reasons. Missing authorization, uncertain ownership, failed checks or a moving target are blockers, not permission to bypass the queue or rewrite history. `/rwbrowser` remains user-invoked only unless already required by task acceptance.
