# Project work

1. Read applicable AGENTS.md and `.pi/project.json`; resolve the Brokan project from that config or verified repository identity. For broad discovery, read [context-economy.md](context-economy.md). Missing or ambiguous mapping blocks edits.
2. Inspect relevant Brokan project and human tasks before creating a new task; reuse the selected task for refinements. Set `todo` then `doing` before edits, with scope, short plan and acceptance criteria in the description. Brokan is the sole task tracker and acceptance authority; never synchronize it with Plane or use `pi-workflow`.
3. For Git changes create or reuse a verified task-owned worktree based on dev (or an explicitly approved persistent branch). Verify repository identity, branch/base SHA, path and exclusive writer ownership. Never edit, stage or commit source directly on dev/main or adopt a foreign worktree. For non-Git runtime edits make a private pre-change receipt/backup and run focused checks. For guarded changes use the source-current formal acceptance gate with a frozen Brokan schema-4 contract; historical Plane contracts remain archival.
4. Run focused checks, required gates and self-review the complete diff. Commit only task-owned changes. Revalidate Brokan task, target ownership, URLs, clean target, exact SHAs, remote dev and the complete proposed remote commit range. Unknown/unrelated ahead commits, divergence, busy/dirty target or stale evidence block delivery. Fast-forward on the verified target with `git merge --ff-only --no-overwrite-ignore <FULL_TASK_SHA>`, push only the verified full SHA with `git push <VERIFIED_REMOTE> <FULL_SHA>:refs/heads/dev`, then fetch and independently `git ls-remote`; prove every delivered SHA is in local and freshly fetched remote dev. Never force, silently include foreign commits or change integration targets to evade a blocker.
5. Immediately after verified delivery, inventory task-owned worktree data, preserve required ignored/untracked data in verified private backup, and attempt normal `git worktree remove` and `git branch -d` only when released, clean, proven merged and owned. Retain uncertain, active, dirty, unknown or data-bearing resources without terminating a session to enable cleanup. Record exact delivered SHAs, target tips, remote URLs, evidence and retained cleanup paths in the Brokan task.
6. Set Brokan status `review` only after complete verified delivery; leave `done` to the user's decision. Main promotion and publishing require separate explicit approval and verified inclusion of every delivered SHA in remote main. Do not invent Git delivery for runtime-only work.
