# Project work

1. Run `pi-workflow context` in the current folder. Read the reported rule files and `.pi/project.json`. For broad discovery or context pressure, read [context-economy.md](context-economy.md).
2. Run `pi-workflow start --title "EXACT TASK TITLE"` for a new change (or reuse the current task pair for refinements). It resolves existing Plane project, states and item or creates Todo and moves it to In Progress. Preserve project/task UUIDs. Missing/ambiguous identity or Plane access blocks edits. For an existing `/factory` selection use `factory-plan` and `factory-start` only; never create a replacement.
3. Define acceptance in the Plane item. For Git implementation, create or reuse a separate, verified task-owned worktree from dev for each affected repo, or from an explicitly approved persistent target. Use native `git worktree add` or another available safe worktree manager. Confirm primary/common-directory identity, base SHA, branch name, path and exclusive writer ownership before writing. Never edit/stage/commit task source on dev/main or adopt a foreign worktree. If isolation cannot be established, stop Git writes. Non-Git configuration uses a scoped owned directory with private backup and focused checks, without requiring a separate workspace manager.
4. Run acceptance checks and inspect the full diff. For guarded tasks collect source-current formal acceptance. Commit only owned Git changes in the task worktree. Reserve integration targets through `megai queue`, then deliver verified task commits to local dev or the explicitly approved target without additional approval; recheck clean target, exact source and target SHAs, and ownership before merge. Fast-forward where required; on moved refs/conflicts reconcile in the owned worktree and reverify. Never force, overwrite ignored data, switch a busy checkout or silently push. Explicit persistent-target exceptions override dev only when authorized.
5. After verified delivery, preserve required ignored data/evidence in a private backup. Remove only a released, clean, task-owned worktree and proven-merged local task branch after fresh ancestry/ownership checks; retain unknown/dirty/active/unmerged resources. Do not use `pi-workflow cleanup`: that legacy command requires an external workspace registry. Keep a receipt JSON listing each affected primary repo and its delivered full commit SHA; for non-Git runtime changes record actual file/evidence results without inventing a Git receipt.
6. Hand off the same task In Review with evidence and remaining risks. For Git deliveries, `pi-workflow review --project-id UUID --task-id UUID --receipt FILE --evidence-file FILE` stores the receipt. Runtime-only changes remain In Review until a user-owned completion decision. Main promotion and push require separate explicit approval; after verified main delivery in every affected repo use `pi-workflow done --project-id UUID --task-id UUID`. Never set Done based solely on local dev or status text.

No agent runner, desktop app, workspace registry or child delegation is a prerequisite for this workflow. Keep integration reservations through required cleanup and release them under their documented contract. Preserve foreign work, local rules and user-owned approvals.
