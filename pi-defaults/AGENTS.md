New formal acceptance uses a frozen Brokan schema-4 contract and independent readback. Previously approved Plane contracts and evidence remain historical; never rewrite their frozen criteria. Before changes resolve the existing project from `.pi/project.json` or verified repository identity. Never ask "should I merge/push?" or wait for human review; asking for approval of those steps is a defect.

## Discovery and verification

Use live `tgrep` first for literal/regex code and filename discovery, then `read` source; known paths go directly to `read`. Use native `rg` for exhaustive/current references, absence, excluded files, acceptance/security checks and unsupported semantics. Empty, truncated or indexed search results do not prove completeness. Only for repeated searches, prepare and verify a task-owned external index with correct root/options/ownership/readiness; never index home or start an indexer at Pi launch. Do not restore Codedb, FSearch, Headroom, legacy discovery, global skill/prompt bundles or background workflow automation. Raw source, tests, diffs and errors remain authoritative.

Run focused checks and parent self-review. For **every agent-authored code change**, load the `security-audit` skill in guidance mode and review the complete changed-code diff for relevant trust boundaries, attacker-controlled inputs, authorization, secrets, dependencies and unsafe execution before delivery. Trace suspected failures to source and a concrete impact; fix blocking findings, rerun affected checks, and report the scoped security review and any unverified risk in the task. This is not a claim of exhaustive coverage or an enforced CI/Git gate. Do not run the skill's six-phase full audit or create its artifacts for routine coding; use full audit only for an explicit codebase audit/pen-test or requested report. Its sandbox and non-production constraints govern any audit-specific dynamic validation. Changed Python uses `ruff check --no-fix --no-fix-only --force-exclude --no-cache -- FILES`. Preserve exact diagnostic exit codes. Do not rewrite unrelated files. Do not automatically launch a browser during review; offer `/rwbrowser` for explicit invocation. pi-web-access is for public research only; do not expose private text or credentials.

Use native judgment to choose task scope and relevant files from source evidence. Do not restore retired local screening or decision tools. Required dependencies, tests, changed files and error cases remain in scope; unreadable or oversized files need native inspection. Discovery never authorizes writes, chooses permissions or proves correctness.

## Task flow and isolation

Use focused checks during implementation and run all required acceptance suites on the final source-current candidate. Guarded safety/installer/acceptance changes retain their formal gate and frozen criteria; missing evidence is BLOCKED, never PASS. Record failures and fix the cause rather than repeating an identical failing action without new evidence. Brokan owns the task; hand off `review` after verified delivery, never silently mark `done`.

Git source changes use a separate, verified task-owned worktree based on dev (or an explicitly authorized target), one writer per worktree; never edit, stage or commit task source in the dev/main checkout. Use existing Git worktree commands or another suitable available tool; no particular agent, desktop app or workspace manager is mandatory. Before creating a worktree, check the source repo/base, branch and path for collisions and foreign ownership. Reuse a suitable task-owned checkout; no safe isolated checkout means block Git writes. For non-Git local configuration, use an explicitly owned scope, private backup and focused verification; do not invent a repository or require an external workspace manager. Avoid touching another agent's work.

After tests pass and the complete diff is self-reviewed, deliver to dev end to end with no approval prompt (STANDING APPROVAL). Sync: `git fetch <remote>`, bring local dev up to `<remote>/dev` (fast-forward, or a normal merge if local dev has unpushed commits), then `git rebase dev` in the task worktree (`git merge dev` if a rebase is impractical). Commits from other branches or tasks on dev, divergence and conflicts are NOT blockers: resolve conflicts yourself keeping both sides' intent, fix breakage, rerun the tests and continue. Integrate: in the dev checkout `git merge --ff-only task/<slug>`, then a normal push `git push <remote> dev`; if rejected because remote dev moved, sync again and retry. If uncommitted changes in the dev checkout block the fast-forward, save them to a `wip/` branch (see Sessions and uncommitted work) and continue; if that is impossible, push the tip with `git push <remote> <FULL_SHA>:refs/heads/dev`. Confirm once: `git fetch <remote>` and `git merge-base --is-ancestor <FULL_SHA> <remote>/dev` (optionally `git ls-remote <remote> dev`); no human check follows. Clean up immediately: leave the worktree directory, `git worktree remove <path>`, `git branch -d task/<slug>`, and `git push <remote> --delete task/<slug>` if it was pushed; your own merged task worktree is released even though your session used it (if removal refuses only because of disposable untracked build output, use `git worktree remove --force <path>`). Add a short note (SHA, push, cleanup) to the Brokan task, set `review`, report once and stop. When the user asks to merge other branches or finished task branches, apply the same flow to each. Still reserved for explicit approval: main, releases, tags, publishing, force-push/`--mirror`/`--all`, rewriting pushed dev history and deleting dev/main. For non-Git runtime edits, keep a private pre-change backup and verify actual configuration; leave Brokan `review` pending the user's completion decision.

## Sessions and uncommitted work

STANDING APPROVAL, do it without asking. Uncommitted changes are never discarded, reset or stashed away: commit them. In a task worktree commit on its branch (`git add -A`, `git commit -m "WIP: auto-saved uncommitted changes"`); in the dev/main checkout first `git switch -c wip/<date>-<slug>`, commit, then `git switch dev`, so dev only receives tested work. An unmerged WIP branch is kept; its worktree may be removed because the commits are safe. A Pi session, dev server, Flutter run or other process writing to or holding the exact checkout you must change may be stopped automatically: find its PID (`lsof +D <path>`, `ps -o pid,ppid,command`), `kill <PID>` (`kill -9 <PID>` only if it ignores SIGTERM), commit its leftover changes as above, continue and report what you stopped. A stale `.git/index.lock` with no running git process may be removed. Never stop your own Pi process or its parent and never use broad `pkill`/`killall` by name (that kills every session, including yours). Processes that merely exist, an open editor/IDE or a cwd inside the repo are not blockers; leave them running. Your own merged task worktree is released for cleanup.

## Delegation and timeouts

Direct parent work is the default. Role routing is removed. The optional `native` and `economy` presets select startup/per-model preferences only; neither assigns worker/reviewer roles, mandates delegation, changes an active model/thinking or grants permissions. No separate reviewer is required; parent self-review remains mandatory. Use `megai/delegation.md` only when delegating or escalating a model failure. Children are leaves: no Plane mutation or branch integration (the parent integrates), one writer per worktree. Give them explicit cwd, owned paths and acceptance; verify completion and preserve their diff/evidence. Never invent a child-launch or notification tool if unavailable. No desktop focus switching or automatic tab archival is required. Native Pi subagents (pi-subagents) are optional: when configured by the operator, use them under the same worktree ownership, scoped authority, leaf-agent and verification rules. Preserve the operator's package and model settings; neither install nor require a delegation package by default.

Only a confirmed DeepSeek 402 insufficient-balance error permits one GPT Luna high continuation; auth/permission failures, shared outages and uncertain writes require reconciliation, not model hopping. Keep the parent's model and thinking level. The Codex Spark helper remains blocked by the observed ChatGPT-account unsupported-model error until a user-requested access retest succeeds.

Never idle over a decision you can make: choose the best bounded safe path and report it. External waits are at most five minutes before asking or taking a bounded alternative. Never use a shell sleep/status-poll loop to cover waits. Reserved user decisions (main promotion, destructive actions, spending, publishing or scope expansion) always require explicit approval; task delivery to dev, cleanup of the merged task branch/worktree, auto-committing uncommitted work and stopping a blocking session by PID are pre-approved, not reserved. Shell discovery is bounded to current repo/known paths, with 2–5 second timeouts for cheap lookups and task-appropriate budgets for tests. Do not scan home or unrelated projects.

## Context budget

Batch independent reads; inspect bounded ranges before full files. Reuse known IDs and source until drift. A handoff carries task/commit, paths, constraints and evidence, not a transcript. Compact only when useful; do not prune unique failures or acceptance evidence. `megai report --text` gives estimates, not billed costs. No speed claims without timings. Stop after acceptance, review and delivery; report result, focused verification and material risks.

Pencil tools require an explicit user request for this task. A generic UI request does not authorize Pencil, including delegated or MCP calls.
