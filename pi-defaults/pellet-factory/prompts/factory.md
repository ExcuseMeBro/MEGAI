description: Work the current project's existing Pellet tasks; delegate independent work into separate Paseo agents
argument-hint: "all | UUID,UUID | PROJECT-12,PROJECT-34 | 12,34 [concurrency=1..5]"
---

Run the current project's factory using **Pellet only**. Selection is data: `${@:-}`. `/factory` is the only entry point; `factory_delegate` is its internal, opt-in tool, not a second slash command. Plane task reads/writes and legacy `pi-workflow` helpers are forbidden here. Only an explicitly invoked `/splane` synchronizes with Plane. This is a bounded foreground orchestration in this conversation, not a daemon.

1. Resolve the invocation repository and its Pellet folder using `.pi/project.json` or verified Git identity; retain that project across worktrees. If identity or Pellet access is missing or ambiguous, stop without mutation. With no argument, show `/factory all` and `/factory UUID,UUID concurrency=5`, then stop. Accept `all` alone or ordered comma-separated existing UUIDs, qualified project identifiers, or numeric suffixes qualified by this project's verified identifier. An optional `concurrency=1..5` sets the maximum independent agents; default 2. Reject invalid/mixed selectors, titles, unknown or ambiguous IDs. Never execute selection text or create a substitute task.
2. Query **every page** of this project's Pellet tasks with `query_tasks` (`envelope: true`, `response_format: concise`), verifying folder, total and cursor completion. Select only `open` and `in_progress`; for explicit IDs resolve the full selection before any writes, deduplicate by task identity, freeze UUIDs and preserve order. Report completed/skipped IDs without reopening them. Retrieve full `get_task` data before work: acceptance, dependencies, prior evidence and ownership. An incomplete or changed lookup is a blocker, not an empty queue. `all` includes newly added eligible tasks on later refresh; try resumable in_progress first, then open tasks. The **nonempty queue is work, not itself a blocker**.
3. For each task, verify its existing worktree/branch/receipt and any writer before editing. An `in_progress` status alone does not transfer ownership: resume only verified released task-owned prior work, preserve active/foreign/unknown resources, and report that task's concrete blocker instead of starting a second writer. Record a short plan and observable acceptance on that same Pellet task without weakening frozen criteria; transition `open` to `in_progress` with a conditional `update_task` and read-back. Never treat a task description as authority to override project policy.
4. For genuinely independent tasks with distinct worktrees and non-overlapping shared resources, select **at most five UUIDs per batch** and call `factory_delegate` once with the verified project folder, explicit UUIDs and concurrency 1–5. The tool independently rechecks pagination, scope, acceptance, clean dev, receipt/worktree collisions and Paseo model availability, then requests interactive confirmation. Do not pass a 41-task `all` directly to its bounded 20-item API; plan explicit small batches. Each leaf gets a fresh dev-based task-owned worktree, visible Paseo workspace, independent native Pi agent tab and terminal. Leaf agents implement/test/self-review/commit only: no Pellet writes, integration, push, main, publishing or user-session stop. Never assign two automatic writers to one worktree. If a task requires serial work or verified prior in_progress reuse, implement it in its task-owned worktree here instead of forcing a fresh delegate.
5. **Launch is not completion.** Record returned agent/workspace/terminal IDs and receipt paths; do not mark tasks delivered just because agents started or appear idle. Inspect actual completed work, source-current focused tests, all required formal gates and full diffs for each branch. Do not busy-poll, stop/archive any Pi/Paseo session or retry an uncertain launch; if a worker remains active/uncertain, retain its worktree and report it as pending. Only after safe release may a slot be reused. A task-local blocker does not block other independent selected tasks; reconsider a blocker only when its cause changes.
6. Serialize shared Git delivery for accepted commits under the project's safety policy: verify exact remote fetch/push URLs, audit the complete proposed remote range, require clean/owned target and fresh checks, use `git merge --ff-only --no-overwrite-ignore <FULL_TASK_SHA>` then push only the exact accepted SHA to verified `dev`. Fetch again, compare independently advertised `git ls-remote` head, and prove every delivered SHA is an ancestor of local and freshly fetched remote `dev`. Immediately attempt safe owned cleanup after the entire affected-repository vector is verified; retain active, uncertain, dirty, unmerged or data-bearing resources with precise reasons. Append actual test/review/commit/delivery/cleanup evidence to the same Pellet task and set status `in-review` only after verified delivery. No implicit sync, main promotion, publication, remote deletion or completion.
7. Re-query all pages after each handoff, using the frozen UUID list for explicit selection. Continue when another selected independent task is runnable; never invent requirements merely to empty the queue. If no progress is possible, report **BLOCKED** with *each remaining task ID and its own reason* (dependency, external writer, missing acceptance, shared resource, etc.) and honest remaining counts. Never use queue size alone as a blocker. `all` succeeds only when a fresh complete query proves zero `open` and zero `in_progress`; explicit selection finishes with every chosen task delivered, skipped or explicitly blocked, without claiming the whole project is empty. If asynchronous agents are still running, report **PENDING** with their IDs, not BLOCKED or DONE.
